왜 만들었나

만성콩팥병은 증상 없이 진행돼, 검진 결과지를 받아도 숫자가 무슨 뜻인지, 오늘 무엇을 해야 하는지 알기 어렵습니다. 병원은 처방과 검사까지만 하고 일상 관리는 본인 몫입니다. 그래서 검진 결과를 넣으면 위험 단계를 알려 주고, 단계에 맞는 생활습관을 매일 실천하게 돕는 서비스를 만들었습니다.

  • 국내 만성콩팥병 환자는 2012년 13만 7천 명에서 2022년 29만 6천 명으로 10년 동안 2배 넘게 늘었고, 진료비는 1조 2천억 원에서 2조 3천억 원이 됐습니다.질병관리청 「주간 건강과 질병」 2024;17:381–382 (팀 결과보고서 인용)
  • 주제는 참여기업 Talos가 제시했고, 기업의 관여는 주제 제공까지였습니다.
  • 검진 입력 → 위험 단계 배정 → 챌린지 → 대시보드까지 화면 전체와 API — 팀원이 도운 화면과 로직도 이어받아 하나로 통합
  • 결과지 사진·PDF에서 수치 10종 자동 입력 (OCR)
  • DB를 PostgreSQL로 교체하고 운영 중 스키마 변경 16번 무중단 적용
  • 보안 필수 항목 8건, 동시 접속 50명 부하 테스트에서 조회 P95 18ms
  • AWS EC2에 접속해 Docker 컨테이너를 띄우는 배포 담당

문제결과지 사진을 올리면 수치가 자동으로 채워져야 하는데, 표 형식 결과지에서 고밀도콜레스테롤 값이 총콜레스테롤 칸으로 들어갔습니다.
판단OCR이 글자 조각마다 줄을 바꿔 한 행이 흩어진 것이 원인이었습니다. 줄바꿈 신호가 아니라 글자의 위치로 행을 판단해야 한다고 봤습니다.
조치좌표로 같은 행을 다시 묶고, “고밀도·저밀도”가 들어간 행은 총콜레스테롤로 매핑하지 않게 막았습니다. 두 줄짜리 고밀도콜레스테롤 칸은 칸 경계를 기준으로 따로 읽습니다.
결과혈압·공복혈당·콜레스테롤 등 10종을 자동으로 채우고, 여러 쪽짜리 PDF는 쪽 단위로 나눠 처리합니다.

받은 템플릿의 MySQL로는 형태가 바뀌는 기록과 의료 수치를 함께 담기 어려웠습니다.

왜 만들었나

클론이 많이 답하는 것보다, 틀린 답이 전문가 이름으로 나가지 않게 하는 것이 먼저라고 봤습니다. 그래서 전문가가 확인하고 운영자가 승인한 내용만 답하도록 설계했습니다.

  • 코치·크리에이터·전문가가 자기 자료로 AI 클론을 만들어 더 많은 사람에게 답하게 하는 서비스 Delphi가 270만 달러 투자를 받았습니다.VentureBeat, 2023.09.06
  • 에어캐나다 챗봇이 환불 규정을 잘못 안내하자, 재판소는 회사가 책임져야 한다고 판단했습니다. 가트너는 챗봇 답변을 사람이 미리 검토·승인하는 절차를 권했습니다.CIO 코리아, 2024.02.21
  • 브리프 → 요구사항 → 구조 설계 순으로 구현 전에 문서로 확정 (총 6,747줄)
  • 전문가 교정과 운영자 승인을 거친 지식만 공개하는 검증 루프 구현
  • 기능을 스토리 단위로 나눠 구현 문서 18건, 에픽마다 회고와 보류 목록 관리
  • 공개 범위를 단계로 나눈 로드맵 — 내부 정교화 → 팬 상담 → 리포트 → 멀티 클론

지식이 공개되기까지

  1. 전문가가 클론의 지식을 채팅으로 읽고, 틀린 곳은 고쳐 달라고 요청
  2. 운영자가 요청을 검토해 승인하거나 반려
  3. 승인된 지식만 지식베이스에 반영 — 승인을 되돌릴 수도 있음
  4. 회원이 상담을 받고, 대화를 바탕으로 리포트를 받음

상담 리포트 · 5부 구성

  1. 상황 요약 — 상담 대화에서 고객의 상황을 정리
  2. 진단 — 무엇이 문제인지
  3. 프레임워크 대입 — 전문가의 방법론에 맞춰 보기
  4. 처방 3가지 — 바로 해 볼 수 있는 조치
  5. 근거 — 진단·처방마다 출처 표시, 근거 없는 내용은 넣지 않음
