판단과 근거

부트캠프가 제공한 MySQL + Tortoise 템플릿을 PostgreSQL 16으로 교체했습니다(ADR-0001). PointTransaction.extra, UserChallenge.last_emotion 같은 가변 메타데이터에 JSONB가 필요했는데 MySQL 8.0에는 JSON만 있어 기각했고, 혈압·혈당·eGFR 같은 의료 데이터의 트랜잭션 무결성 때문에 MongoDB를, 다중 사용자 동시 쓰기 때문에 SQLite를 기각했습니다. RAG 임베딩을 pgvector로 같은 DB에서 처리할 여지도 고려했습니다.

ORM은 SQLAlchemy가 동기 기본이라 async 설정 부담이 있어, 비동기 우선이고 aerich 마이그레이션이 통합된 Tortoise를 유지했습니다. 트레이드오프(멘토의 PostgreSQL 경험 부족, Tortoise 커뮤니티 규모, JSONB 인덱싱 비용)는 ADR에 그대로 적었고, 운영 중 마이그레이션 16개를 무중단으로 적용했습니다.

프론트는 백엔드를 FastAPI로 분리한 이상 Next.js는 기능이 겹쳐 기각하고 Vite + React 19 + TS strict + Tailwind v4로 갔습니다(ADR-0002). 상태의 90%가 서버 상태라 Redux/Zustand는 과대하다고 보고 TanStack Query 캐싱으로 처리했으며, 고령 사용자를 고려해 번들을 가볍게 잡았습니다.

검진지 OCR에서는 표 형식 결과지의 총콜레스테롤 칸이 HDL 값을 가로채는 오탐이 반복됐습니다. CLOVA OCR이 글자 조각마다 줄바꿈 신호를 보내 한 행이어야 할 글자들이 흩어진 것이 원인이었습니다. 줄바꿈 신호 대신 글자 조각의 좌표로 같은 행을 다시 묶고, “고밀도·저밀도”가 들어간 행은 총콜레스테롤로 매핑하지 않도록 막았으며, 두 줄짜리인 HDL 셀은 셀 경계를 기준으로 읽는 전용 규칙을 따로 두었습니다.
